# логика PoC 
приложение использует конфиденциальный клиент без pkce и имеет намеренно уязвимую страницу /lab где можно проверить:
```
<script>alert(document.cookie)</script>
<script>alert("1")</script>
```

Само приложение после аутентификации дает cookie с флагами httpOnly, SameSite=Lax
Суть PoC показать что несмотря на защиту cookie его можно угнать через xss когда пользователь аутентифицировался ранее.

Состоит из 3 этапов:
- xss инициирует скрыто от пользователя новый поток аутентификации
- поток запрашивается с response_mode=fragment но приложение умеет работать только с query поэтому происходит прерывание, auth code приложение получает но не успевает обменять и отправляется на PoC сервер (атакующему)
- PoC сервер получив код на /capture делает запрос на api клиента (backend приложения) /callback которая полчив код обменивает его и отправляет атакующего валидную cookie пользователя
